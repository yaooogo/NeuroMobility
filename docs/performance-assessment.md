# 用户30天业绩考核与月度成长奖励

成长奖励与扣减分开结算：成长奖励仍每月1号生成，保存于`wallet_growth_snapshot`，发放毛利分成时读取发放当月的成长加成，没有当月快照时为0。其增长仍按最近历史月度快照比较，首次月度快照只建立基准。月度成长不要求用户已首次升级。

首次自动升级后次日北京时间00:00开始首个考核期，每期固定30天，采用左闭右开区间。2026-11-13升级，对应首期为[2026-11-14 00:00:00, 2026-12-14 00:00:00)，第二期截止2027-01-13 00:00:00。后续升级、降级不重置锚点。未记录首次升级时间的历史用户不推定锚点。

`wallet_performance_snapshot`保存周期起止时间、考核时有效等级、期初和期末社区业绩、正增长、命中的达标金额与四项扣减值，不生成成长加成。表内原growth_percent与whole_vehicle_count兼容字段不再参与计算。社区业绩只计USDT本金，混合订单按下单时USDT占比折算；增长=max(期末-期初,0)。同等级命中最低的未达标金额规则，达到全部门槛不扣减。

首次完成30天考核前，扣减为0，成长加成仍由当月成长快照决定。扣减结果在周期结束时生效，奖励读取period_end不晚于实际发放时间的最新考核快照，直至下一期结果生效。配置变更不修改已生成快照。扣减按百分点计算，每个分项最低为0：

- 毛利有效比例=max(等级毛利比例-快照毛利扣减,0)+max(快照成长加成-快照加成扣减,0)，再按等级计算级差。
- 拓展有效比例=max(等级拓展比例-快照拓展扣减,0)，再按等级计算级差。
- 直属上级激励比例=max(配置激励比例-该直属上级快照激励扣减,0)。

分红任务和投资入口在发奖前生成已到期快照，事务锁定钱包并由(wallet,period_end)唯一键防重。延迟执行按固定边界逐期补算，不把执行日作为新周期起点。生成失败时阻止该次发奖流程，避免继续使用过期扣减。

`growthSnapshot.js`负责月度成长快照，并先调用`performanceSnapshot.js`生成到期的30天扣减快照；毛利发放分别连接两张表，月初不会重置30天扣减周期。新表和`investment_order.performance_ended_at`支持运行时建表/补列，也可先执行SQL迁移（根据部署调整n_前缀）。首次升级字段需已部署。

边界业绩从订单创建和停止贡献时间还原，不依赖异步刷新的钱包统计。旧已退出/终止订单的停止贡献时间使用updated_at回填；旧数据被后续编辑过时可能存在误差。推荐关系未保存完整历史，因此补算使用当前推荐关系。延迟补算的等级和奖励规则使用执行时配置，系统没有历史配置/等级版本可还原。新订单退出或后台终止时会明确保存停止贡献时间。

验证：`node --test api/tests/PerformanceAssessment.test.js`。测试使用内存数据库替身，不连接真实数据库。
